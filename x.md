# ByteTrack vs BoT-SORT experiment

## Outcome

`experiment.py` runs the same prerecorded video twice:

1. A fresh YOLOv8l detector with `bytetrack.yaml`.
2. A fresh YOLOv8l detector with `botsort.yaml`.

It automatically prints and saves one pandas DataFrame containing:

- HOTA, DetA, and AssA
- IDF1
- MOTA
- Identity switches and fragmentations
- False positives and false negatives
- Precision and recall
- Median and P95 end-to-end processing latency
- Processing throughput in FPS

No existing function or function parameter is modified. The runner reuses `Detector` for
model initialization and reads the underlying Ultralytics tracking results directly because
the existing `Detector.track()` return type intentionally does not expose track IDs.

## Required inputs

### 1. Prerecorded video

Place the stationary-camera evaluation video here:

```text
evaluation/stationary_webcam_eval.mp4
```

Alternatively, change only `VIDEO_PATH` at the top of `experiment.py`.

Recommended video:

- `30–60` seconds
- Stationary laptop camera
- Two or more people
- At least one crossing or brief occlusion
- Some movement toward and away from the camera
- Normal representative indoor lighting

The default experiment evaluates COCO class `0` (`person`). Change `EVALUATED_CLASS_IDS` only
if a different class is required.

### 2. Ground-truth identities and boxes

Automatic tracking accuracy cannot be derived from video alone. Each visible evaluated object
needs a ground-truth bounding box and persistent identity on every frame.

Create:

```text
evaluation/ground_truth.txt
```

Use MOTChallenge-style rows:

```text
frame,id,x,y,width,height,confidence,class,visibility
```

Example:

```text
1,1,100,120,80,220,1,1,1
2,1,102,120,80,220,1,1,1
1,2,500,125,75,215,1,1,1
2,2,496,125,75,215,1,1,1
```

Rules:

- Frame numbers start at `1`.
- Coordinates are absolute pixels, not normalized values.
- `x,y` is the top-left corner.
- Keep the same `id` while the same real person remains in the sequence.
- Annotate only people when `EVALUATED_CLASS_IDS = (0,)`.
- Set confidence to `1` for valid ground-truth rows.
- A template is available at `evaluation/ground_truth.example.txt`.

An annotation tool may be used as long as its export is converted to the row format above.
Dense frame-level annotations are needed for official-style HOTA, IDF1, and MOTA values.

## Setup

The experiment adds no new dependency beyond pandas and SciPy, which are already installed in
the current environment. For another environment:

```powershell
python -m pip install -r requirements-experiment.txt
```

The existing Ultralytics, PyTorch, and OpenCV installation is reused.

## Configuration

The variables intended for adjustment are grouped at the top of `experiment.py`:

```python
VIDEO_PATH = Path("evaluation/stationary_webcam_eval.mp4")
GROUND_TRUTH_PATH = Path("evaluation/ground_truth.txt")
OUTPUT_DIR = Path("evaluation/results")

EVALUATED_CLASS_IDS = (0,)
DETECTION_CONFIDENCE = 0.10
BRIGHTNESS_VALUE = config.BRIGHTNESS_CENTER
MATCH_IOU = 0.50
WARMUP_FRAMES = 5
SAVE_ANNOTATED_VIDEO = True
```

The tracker order is explicit:

```python
TRACKERS = {
    "ByteTrack": "bytetrack.yaml",
    "BoT-SORT": "botsort.yaml",
}
```

Both runs therefore use identical video frames, YOLO weights, class filters, confidence,
resolution, brightness adjustment, blur, device, and evaluation thresholds. A new detector is
created for each run so tracker state cannot leak between them.

`DETECTION_CONFIDENCE = 0.10` supplies low-confidence detections to the trackers, matching
Ultralytics tracking behavior. The application's display hysteresis is deliberately not
applied because the purpose is to compare tracker association rather than UI filtering.

## Run

After adding both input files:

```powershell
python experiment.py
```

The script validates the paths and ground-truth format before evaluation. It then processes
the complete video with ByteTrack followed by BoT-SORT and prints a DataFrame similar to:

```text
          Frames  HOTA (%)  DetA (%)  AssA (%)  IDF1 (%)  MOTA (%)  IDSW  ...
Tracker
ByteTrack    ...      ...       ...       ...       ...       ...     ...
BoT-SORT     ...      ...       ...       ...       ...       ...     ...
```

## Outputs

The runner creates:

```text
evaluation/results/
├── bytetrack.mp4
├── bytetrack_predictions.csv
├── bot_sort.mp4
├── bot_sort_predictions.csv
└── tracker_comparison.csv
```

The exact filename casing follows the tracker label generated by the script. The annotated
videos are useful for visually auditing unexpected metrics. Rendering and video encoding are
excluded from the latency measurements.

## Metric derivation and interpretation

### IoU matching

Ground-truth and predicted boxes are paired using Intersection over Union:

```text
IoU = area(prediction ∩ ground truth) / area(prediction ∪ ground truth)
```

For IDF1 and CLEAR/MOTA metrics, a match requires `IoU >= MATCH_IOU`, which defaults to `0.50`.

### HOTA

At each localization threshold `α`:

```text
DetAα = TP / (TP + FP + FN)
HOTAα = sqrt(DetAα × AssAα)
HOTA  = average HOTAα for α = 0.05, 0.10, ..., 0.95
```

`AssA` measures how consistently matched ground-truth and predicted trajectories remain
associated. HOTA balances finding objects (`DetA`) with maintaining identities (`AssA`).

Interpretation:

- Higher is better; `100%` is perfect.
- Similar DetA but higher AssA means better tracking association.
- Lower DetA points to missing or additional boxes rather than identity association alone.
- There is no universal pass score; compare both trackers on the same video.

### IDF1

After globally assigning predicted trajectories to ground-truth identities:

```text
IDF1 = 2 × IDTP / (2 × IDTP + IDFP + IDFN)
```

- `IDTP`: correctly identified object observations.
- `IDFP`: predicted observations assigned to the wrong identity.
- `IDFN`: ground-truth observations missed or identified incorrectly.

Interpretation:

- Higher is better; `100%` is perfect.
- High recall but lower IDF1 means objects are detected but their identities are unstable.
- IDF1 is important here because application hysteresis and label history are keyed by ID.

### MOTA

```text
MOTA = 1 - (FN + FP + IDSW) / ground-truth detections
```

Interpretation:

- Higher is better; `100%` is perfect.
- MOTA can become negative when accumulated errors exceed ground-truth detections.
- FP and FN often dominate it, so interpret it alongside IDF1 and AssA.

### Identity switches and fragmentations

```text
IDSW = number of times one ground-truth trajectory changes predicted identity
Frag = number of times a tracked ground-truth trajectory is interrupted and later resumed
```

Lower is better for both. IDSW is especially easy to audit in the saved annotated videos.

### Precision and recall

```text
Precision = TP / (TP + FP)
Recall    = TP / (TP + FN)
```

Precision measures how many output boxes are valid. Recall measures how many visible
ground-truth objects are successfully tracked.

### Latency and FPS

```text
P95 latency = the frame time that 95% of measured frames meet or beat
FPS         = 1000 / mean frame latency in milliseconds
```

Median latency represents a typical frame; P95 reveals intermittent stutter. The first five
frames are excluded from timing summaries as warm-up, but remain included in tracking metrics.
Lower latency and higher FPS are better.

## Decision rule

Use the stationary-camera result as the primary decision:

1. Compare HOTA, then inspect DetA and AssA to identify the source of the difference.
2. Prefer higher IDF1 and fewer ID switches when detection accuracy is similar.
3. Reject gains caused only by worse precision or recall elsewhere.
4. If tracking quality is effectively tied, prefer the tracker with lower P95 latency and
   higher FPS.
5. Evaluate moving-camera footage separately as an optional future capability.

For this fixed laptop-camera use case, ByteTrack is the simpler baseline. BoT-SORT should be
selected only if its measured association quality justifies its sparse-optical-flow overhead.
